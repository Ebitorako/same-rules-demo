## Who you are working with

The person directing you is the team's designer and artist, not a programmer.

- Explain what you changed in plain language, briefly. No jargon without a one-line explanation.
- Work in small steps. After every task the game must still build and run.
- End every task with **how to try it**: the command to run and exactly what to click or look at.
- If something in the spec is unclear or marked as an open decision, use the default in the spec and say so; do not stop.
- Ask before adding a dependency, changing a game rule, or rewriting a large part of the code.

## Stack and commands

Vite + TypeScript, no UI framework, no game engine, no backend. `papaparse` for CSV, `vitest` for tests. Deployed to GitHub Pages via GitHub Actions.

```bash
npm install
npm run dev            # local preview
npm test               # unit tests (game logic)
npm run validate-data  # checks public/data/*.csv; readable errors for non-programmers
npm run build          # production build
```

Keep these script names working; create them during M0 if they do not exist yet.

## Non-negotiable rules

1. **Same start, hidden rules during play.** Both pawns start with Creativity 3, Communication 3, Network 2, Reputation 2, Availability 2 and Energy 7. These are the six current stats. Hide numerical stats and gender effects during play and YOUR CHOICES review, except with `?debug=1`. At a terminal ending show six final values and its recorded choice/system-event recap. Chapter milestones do not reveal numerical values.
2. **Deterministic.** No randomness in outcomes. `Math.random` is allowed only for the optional round-1 random gender (config).
3. **No undo.** No back button or save slots; auto-save the current run so a refresh resumes, not rewinds.
4. **Story text comes from data.** The canonical runtime authority is `public/data/team-content.json`, generated from the read-only English sheet snapshot by `scripts/import-team-content.mjs`. Chinese display text comes from `public/data/zh-CN.json`, generated by `scripts/import-chinese-content.mjs` from the paired Chinese source snapshot. Both languages share mechanics, IDs and canonical saved history; never change a branch or replay a choice when switching language. The public scenario/ending CSVs and copy/candidate/policy JSONs are review exports, not independent runtime inputs. Guide identity/fallbacks and asset mappings remain separate. Never hard-code story, option, result or ending text in UI code.
5. **Gender logic is data-driven** (per-pawn options, results, deltas and effects). Keep visible branch conditions separate from numeric availability gates. A card may have one, three or four options; a locked choice opens its supplied thought without spending it. No `if (female)` story branches in UI code.
6. **Preserve approved art.** The designer supplies the character designs and has authorised extracting/cleaning the two pawn and four Boss illustrations into game assets. Preserve their identities; do not independently design additional characters. The extra Boss reaction requirement is cancelled; reuse the existing Boss illustrations. CH1-E01 uses `public/assets/cards/ending_CH1-E01.png` for both pawns. CH2-E07 is one logical milestone with two approved files, `ending_CH2-E07_male.png` and `ending_CH2-E07_female.png` in the same directory, selected by the current pawn; never assume a base `ending_CH2-E07.png` exists. The current handoff has 59 logical assets and 60 installed PNGs, excluding the homepage poster, with no pending visible placeholders. Preserve reviewed bytes. The local `art/approved/2026-11-03/` overview and `milestone-provenance.json` retain final approval and generation records; obsolete milestone review pages are no longer active sources. Art requirements and prompts live in `docs/ART_REQUIREMENTS.zh-CN.html`, generated by `docs/tools/build-art-brief.mjs`; do not recreate duplicate handoff manuals. Use the colour tokens in the spec. The six special tiles and four Boss history-card faces may use the approved metallic backgrounds; character files remain transparent.
7. **No `window.alert` / `confirm` / `prompt`.** Use in-page dialogs.
8. **Accessibility:** real `<button>`s, keyboard play (`1`–`4`, `Enter`), visible focus, respect `prefers-reduced-motion`. Player-facing choice numbers use numeric options, not source branch labels such as D. Sound is optional and must never be needed to understand or complete a scene.

## Code conventions

- Game logic in `src/game/` as pure functions (`state + action → state`), unit-tested. Rendering in `src/ui/`. Tunable numbers and open decisions only in `src/config/rules.ts`.
- TypeScript `strict`. Small files. Clear names over comments; comment only the why.
- Do not delete or edit files in `public/assets/` or `public/data/` unless asked.
